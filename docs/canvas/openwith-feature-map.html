本地优先

服务只监听 127.0.0.1，Bearer token 鉴权，2 MB 请求上限，命令走显式 allowlist；面板没有文件系统与进程权限。

service/main.ts安全边界

六条设计原则

  • 面板不碰特权：iframe 只有 DOM 与宿主桥，读文件、跑命令、开进程都在 service。
  • 服务不出本机：127.0.0.1 + token，所有响应统一 {ok,data} / {ok,error,detail}。
  • 配置深合并：默认配置与用户配置递归合并，数组整体替换，迁移由 configStore 统一处理。
  • 宿主桥按作用域复用：workspace 与 shells 共享同一条宿主通道，避免 32 条订阅上限。
  • 窄面板优先：约 406 px 宽度下仍可用，窄屏自动换行、单列表单、上下布局。
  • Windows 优先但不锁死：命令与路径按平台探测，WSL 作为一等资源，Linux/macOS 走兼容分支。
一句话理解：OpenWith 是 OpenChamber 里的“窗口管理器 + 资源启动器”。它不替代扩展，而是把扩展、网页、终端和本机服务放进同一个可保活的标签工作台。

02运行拓扑

三个执行域：沙箱面板、宿主桥、本机服务；外部进程由服务按 allowlist 拉起。

谁可以碰什么，一眼看清

面板域

只能画界面、读宿主 storage、发 serviceRequest。没有 Node、文件系统、子进程与任意网页 iframe。

信任级别：低sandbox

桥接域

宿主注入 token 并转发请求；给嵌入扩展签发 frame-grant、转发宿主 API、按作用域复用订阅。

信任级别：中host

服务域

唯一能碰配置、日志、网络和子进程的地方；所有输入按控制器校验，命令必须在 allowlist 内。

信任级别：高loopback

一次请求怎么走

面板发起 serviceRequest视图只描述意图，例如读取快照或启动一个应用；不直接访问网络。
宿主桥补上鉴权把请求转发到本机服务端口，附带 Bearer token；跨域与 CSP 留在宿主侧处理。
服务路由分发service/main.ts 按路径找到控制器，校验参数、读取配置、调用子进程或宿主 API。
统一信封返回成功 {ok:true,data}，失败 {ok:false,error,detail}；面板按错误码显示可操作提示。
视图增量更新标签页保活，只有当前可见视图重绘；后台标签保留状态，切回时不丢滚动与输入。

03标签系统

五类标签页共享同一套生命周期：创建、保活、置顶、排序、分屏、恢复。

点上面的标签切换细节

matrix-home · 矩阵主页

默认七个主页标签：扩展、扩展市场、Windows 应用与 ShardX、WSL2、Docker、Kubernetes、云与 Webhook。每个标签是一组资源卡片，可切换列表 / 卡片 / 紧凑视图。

  • 标签可改名、排序、隐藏；删除内置标签后可从编辑器恢复。
  • 自定义分组自动生成主页标签，按用途归类资源。
  • 分页大小默认 8，最小 3；统计卡片可点击跳到对应分组。
  • 编辑入口分层：分组、资源、动作各自独立，避免一个弹窗塞满。
7 个默认主页标签扩展 / 市场 / 应用 / WSL / Docker / K8s / 云
3 种视图卡片 · 列表 · 紧凑，逐标签记忆
自定义分组自动生成标签，可重命名与排序

guest-extension · 嵌入扩展

把其他 OpenChamber 扩展的面板嵌进标签页。宿主先签发一次性 frame-grant，面板用 /api/guest-files/{grant}/panel/index.html 加载，再通过 postMessage shim 转发宿主调用。

  • 按扩展自己声明的入口加载；纯文件编辑器（Excalidraw 等）走 fileEditors 入口并注入空白文档，不再白屏。
  • 跟随宿主会话切换；Agent progress 等扩展显示当前会话进度。
  • 转发 service-status、file-open、附加到聊天与目录切换。
  • workspace / shells 订阅按作用域去重，避免 32 条订阅上限。
frame-grant一次性、带过期时间，只授权单个扩展
postMessage shim宿主 API 与面板之间的唯一通道
会话跟随切项目 / 切会话时内嵌面板同步更新

web-iframe · 网页标签

面板本身不允许任意 iframe，网页标签由服务侧的无头 Chrome / Edge 通过 CDP 渲染，再把画面与输入转发到面板。

  • 帧轮询 + 输入转发，保留点击、滚动与键盘。
  • 适合本地端口、WSL 服务、内网面板与文档页。
  • URL 支持模板变量，切项目时自动替换。
  • 浏览器路径可在设置里指定（browser.chromePath）。
CDP 渲染Chrome / Edge headless
帧轮询画面与输入双向转发
变量化 URL{path} / {wslIp} / {projectName}

log-stream · 日志流

订阅本机服务日志，实时追加；服务重启后自动重新订阅，不会停在 subscription-not-found。

  • 日志文件：~/.config/openchamber-openwith/logs/service.log。
  • “发送到 AI”会截断旧日志以适配宿主 16000 字符限制，并显示真实结果。
  • 适合排查服务启动、命令失败、市场抓取与代理问题。
service.log按时间追加，面板只读
自动重订阅服务重启后恢复流
发送到 AI截断旧行，保留最近上下文

terminal-exec · 终端

在服务侧执行命令并把输出流回面板。默认 shell 为 PowerShell，可切换 bash / sh；所有可执行文件必须在 permissions.exec 白名单内。

  • 命令模板支持 {path}、{winPath}、{projectName} 等变量。
  • 过滤 PowerShell 的 CLIXML 进度噪声，只显示命令结果。
  • 终端标签可保活，切走再切回不丢输出。
PowerShell 默认settings.terminalShell
allowlist未声明的命令直接拒绝
变量模板项目路径 / 分支 / WSL IP

06宿主桥

嵌入扩展与 OpenChamber 宿主之间的协议层：授权、转发、订阅、生命周期。

panel/guestBridge.ts

frame-grant 五步

请求授权面板为某个 guest 申请 frame-grant；宿主校验扩展是否启用、入口是否存在。
签发 grant返回一次性 grant 与过期时间，绑定扩展 id 与面板来源。
加载 iframe使用 /api/guest-files/{grant}/panel/index.html（或扩展声明的入口）加载。
注入 shimpostMessage shim 提供宿主 API：storage、serviceRequest、service-status、file-open、会话与目录。
按作用域订阅workspace / shells 共享通道，去重后复用；标签关闭时释放订阅。

storage

宿主侧键值存储；面板不直接碰 localStorage，避免沙箱与同源限制。

serviceRequest

统一转发到本机服务，自动附带 token；面板无需知道端口与鉴权。

service-status

服务启动 / 停止 / 异常状态推送，Canvas 等扩展的设置页不再报“尚未桥接”。

file-open

纯文件编辑器扩展按 fileEditors 入口打开并注入空白文档，Excalidraw 可直接画图。

会话跟随

宿主切换项目 / 会话时，内嵌面板同步更新；Agent progress 显示当前会话。

附加到聊天

把 Canvas 产物等引用转发进输入框，形成“面板 → 对话”的工作流。

两个硬限制：frame-grant 有有效期，过期后必须重新申请；每个 frame 最多 32 条 workspace 订阅，因此同一作用域必须复用通道。桥接层负责去重与释放，视图层不要自行重复订阅。

安全边界清单

面板

  • allow-scripts，无 same-origin 存储。
  • 严格 CSP，不允许任意 iframe。
  • 不接触 Node、文件系统、子进程。

桥

  • frame-grant 一次性、带过期。
  • 只转发已启用 guest 的请求。
  • 订阅按作用域去重并释放。

服务

  • loopback + Bearer token。
  • 2 MB 请求体上限。
  • 命令 allowlist，参数按控制器校验。
配置写入：先写临时文件再原子替换；版本号用于迁移。读取时默认配置与用户配置深合并，数组不逐项合并，避免“删不掉的旧项”。

09构建与发布

TypeScript 源码 → Bun 打包 → dist/ → GitHub Release / release 分支。

Node 20+ · npm 10+ · Bun 1.3.x

本地命令

npm ci
npm run typecheck   # tsc --noEmit
npm run build       # scripts/build.mjs
npm test            # typecheck + build

构建产物在 dist/，永远不提交；源码与已安装副本的 dist 不应漂移。

Bun 执行 @openchamber/sdk 的 bundle-guest本地

发布流程

push main构建并发布滚动 latest Release，同时刷新 orphan release 分支。
push tag vX.Y.Z发布版本化 Release，同样刷新 release 分支。
附件两种路径都附带同一个构建 zip，供下载安装。
.github/workflows/release.ymlCI
安装方式：把 dist/ 作为文件夹扩展安装，或用仓库 git URL 安装；宿主比较 package.json 版本决定是否更新。release 分支只含构建产物，单 commit，可原地更新。

四个扩展点

1 · 新增资源分区

  1. 在 shared/types.ts 增加类型与默认值。
  2. 在 config/default-matrix.json 加空数组 / 示例。
  3. 服务快照聚合该资源，必要时加控制器与路由。
  4. 在 panel/views/ 加卡片、编辑器与动作。
  5. 补 changelog、ARCHITECTURE、CONFIG 与 README 双语文档。

2 · 新增标签页类型

  1. 在标签类型联合里加新 kind，并定义持久化字段。
  2. 在 panel/main.ts 的标签工厂注册创建 / 恢复逻辑。
  3. 在 tabManager.ts 处理保活、置顶、分屏与上限。
  4. 如果是 guest，走 guestBridge.ts 的 grant 与 shim。
  5. 更新新标签菜单、图标与文档。

3 · 新增服务能力

  1. 在 service/main.ts 注册路由，写清方法与错误码。
  2. 控制器放在 service/，只返回数据，不碰 DOM。
  3. 需要新命令时，把可执行文件加入 permissions.exec。
  4. 在 shared/types.ts 定义请求 / 响应类型。
  5. 补路由表文档与 changelog。

4 · 新增模板变量

  1. 在变量上下文中解析新值（路径、分支、IP 等）。
  2. 在 /variables/expand 支持替换。
  3. 在面板的变量提示与输入校验中展示。
  4. 更新 CONFIG 文档与本文“模板变量”表。

每次改完的检查单

  • 在 changelog.md 顶部加一行：- 新增|优化|修复 YYYY-MM-DD 描述。
  • 同步 README.md 与 README.zh-CN.md；更新受影响的 docs/。
  • 运行 npm run typecheck 与 npm run build，必要时 npm test。
  • 行为变更时，把 dist/ 作为文件夹扩展安装并按 BASELINE §5 验证。
  • 不提交 dist/、node_modules/、日志、本地配置或密钥。
  • 面板在约 406 px 宽度下仍可用；新增命令已加入 exec allowlist。
更新这张地图：编辑 docs/canvas/openwith-feature-map.html，用 Canvas 以同一个 dedupeKey 重新发布；在 changelog 记一行“优化 功能地图”。本页是静态 HTML，无外部依赖，可直接作为迭代基线。
